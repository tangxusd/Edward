# Edward 0.4.0 Resolve Studio 基座实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不重新实现完整剪辑引擎的前提下，让独立 Edward 通过 Resolve Studio 适配器读取项目状态、编辑字幕组件并调用 Resolve 渲染。

**Architecture:** 新增独立 `edward_resolve` 模块，隔离 Resolve 连接、JSON-RPC/MCP 通信和版本能力探测。`WorkbenchRuntime` 只依赖稳定的适配器接口；Component IR 继续作为组件编辑真相，Resolve 作为时间线和渲染真相。第一条可验收链路是“连接 Resolve -> 读取播放头 -> 生成字幕 IR -> 添加到时间线 -> 写入关键帧 -> Edward 简化导出或 Resolve 原生高级导出”。

**Tech Stack:** C++20、Qt 6 Core/Network、现有 CMake/CTest、现有 `edward_core` Component IR、Resolve Studio Lua/Python API 适配桥接。

## Global Constraints

- 只支持用户已安装的 DaVinci Resolve Studio，不适配免费版。
- Edward 是独立外部应用，不安装到 Resolve 内部，不修改 Resolve 安装目录。
- Resolve 的项目、时间线、播放头、轨道和渲染是最终真实状态。
- Component IR 只保证标准子集；无法转换的属性必须明确报告，并保留透明视频回退。
- 预览坐标中心为 `(0, 0)`；左为正 X、右为负 X、上为正 Y、下为负 Y。
- 不使用系统级模拟点击隐藏 Resolve 面板；Edward 只提供自己的简化工作区。
- 不把 API key、用户凭证或 Resolve 私有路径写入源码或测试夹具。
- 每个任务先写失败测试，再写最小实现；相关 CTest 和构建通过后再提交。

## 文件结构

**新增模块：**

- `src/resolve/include/edward/resolve/resolve_types.hpp`：连接状态、时间线快照、轨道/播放头、渲染状态和错误类型。
- `src/resolve/include/edward/resolve/resolve_connection.hpp`：JSON-RPC/桥接传输接口，禁止出现 UI 或业务逻辑。
- `src/resolve/include/edward/resolve/resolve_adapter.hpp`：面向 Edward 的 Resolve 操作接口。
- `src/resolve/src/resolve_connection.cpp`：本地桥接进程/套接字通信和 JSON 编解码。
- `src/resolve/src/resolve_adapter.cpp`：能力探测、快照读取、媒体/字幕/Fusion/渲染调用。
- `src/resolve/CMakeLists.txt`：`edward_resolve` 静态库及 Qt Network 依赖。
- `tests/resolve/test_resolve_connection.cpp`：传输层协议和错误测试。
- `tests/resolve/test_resolve_adapter.cpp`：适配器行为测试，使用内存 RPC fixture。
- `tests/resolve/fixture_rpc_server.cpp`：不连接真实 Resolve 的确定性协议夹具。

**修改模块：**

- `CMakeLists.txt`：加入 `src/resolve` 和 `tests/resolve`。
- `src/desktop/include/edward/desktop/workbench_runtime.hpp`：注入 Resolve 适配器、连接状态和字幕/导出 Q_INVOKABLE。
- `src/desktop/src/workbench_runtime.cpp`：把 UI 操作转换为适配器调用；不得直接拼接 RPC JSON。
- `src/desktop/CMakeLists.txt`：链接 `edward_resolve`。
- `src/desktop/qml/Workbench.qml`、`EdwardPreview.qml`、`EdwardTimeline.qml`：显示连接状态、字幕组件入口和双导出入口。
- `tests/desktop/test_timeline_controller.cpp` 或新增 `tests/desktop/test_resolve_workbench.cpp`：桌面层只验证适配器调用和错误呈现，不验证真实 Resolve。
- `docs/operation-log/2026-08-10-001-requirement-audit.md`：追加每个阶段的结果。
