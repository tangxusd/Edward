# Edward 0.3.0 Shotcut/MLT 基座实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 Edward 已确认的视觉界面中，用 MLT 和经过审计的 Shotcut 时间线逻辑建立可导入、可剪切、可分割、可波纹删除、可预览、可导出的基础视频剪辑闭环，并逐级接入标准动画组件、外部插件和资源库上传。

**Architecture:** Edward 工程模型和 Component IR 是唯一编辑真相源；MLT 负责媒体运行时和最终合成。Shotcut 只作为许可证审核后的选择性代码来源，移植时间线行为而不移植其 QML 界面。React、Remotion 和 HyperFrames 通过适配器渲染透明组件层。

**Tech Stack:** C++20、Qt 6.11.1/QML、CMake 3.28.3、Ninja、MLT 7.40.0、FFmpeg 8.1.2、Qt Test、JSON Schema、独立 Node 插件进程和版本化 JSON-RPC。

## Global Constraints

- 保留 Edward 已确认的深色视觉稿和系统原生标题栏，不引入 Shotcut QML 界面。
- 第一版不实现音频波形、混音器、调色页面、完整滤镜和完整转场库。
- 预览和导出必须使用同一 RenderGraph，不允许 QML 绘制第二套导出画面。
- 插件独立进程运行，默认禁止网络，只能访问授权的工程素材和插件缓存目录。
- 所有组件编辑统一修改 Edward Component IR；React、Remotion、HyperFrames 不是工程真相源。
- Shotcut/MLT 源文件导入前必须记录许可证、来源、提交 SHA 和文件归属；不直接复制整个 Shotcut 应用。
- 所有测试使用 CTest 注册，测试名采用小写点分格式。
- 每个阶段完成后追加 `docs/operation-log/` 现有记录，不创建重复日志文件。
