# 支付宝单次购买实施计划

## 目标

以支付宝单次订单替代当前手动测试支付入口，保留现有订阅数据模型，后续可在不重写权益系统的情况下增加自动续费产品。

## 里程碑

1. 审核支付宝正式接口、商户产品权限、回调和 RSA2 密钥配置；输出字段映射表。
2. 为 `orders` 增加支付宝订单合同和幂等索引；补充 Edge Function provider 模块。（RSA2 基础工具已完成，具体产品适配待第 1 步字段确认。）
3. 实现创建、查询、通知三个服务端函数，并用固定签名样例测试金额/商户/状态校验。
4. 接入 Edward 套餐页，支付结果只显示服务端确认状态。
5. 完成沙箱/调试环境验收后，再讨论生产密钥和正式回调部署。

## 当前假设

- 本阶段采用单次购买/手动续费，不启用自动扣款。
- Supabase Edge Functions 是唯一支付服务端；Vercel 只承载公开页面（如需要）。
- 支付宝官方页面 `repo-0038oa` 需要在可访问的商户文档上下文中确认具体产品，不据此猜测接口名。

## 验收检查

- [ ] 官方接口和产品权限已确认
- [ ] RSA2 签名和验签测试通过
- [ ] 金额、商户号、订单号校验通过
- [ ] 重复通知幂等且只授予一次权益
- [ ] 查询可恢复下单超时状态
- [ ] 前端跳转成功但无通知时不授予权益
