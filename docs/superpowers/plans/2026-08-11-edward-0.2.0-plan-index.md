# Edward 0.2.0 模块化实施计划索引

> 本索引取代“由一份总计划覆盖全部实现”的做法。每个模块在前置模块验收通过后才可实施；模块内使用测试先行、最小实现、验证、提交的固定节奏。

## 权威输入

- 需求决定与操作记录：`docs/operation-log/2026-08-10-001-requirement-audit.md`。
- 已确认页面与唯一最终 HTML：`docs/superpowers/specs/2026-08-10-edward-0.2.0-visual-confirmation-manifest.md`。
- 唯一实施规格、需求 ID 与视觉/任务映射：`docs/superpowers/specs/2026-08-11-edward-0.2.0-authoritative-spec-and-traceability.md`。
- 唯一 C++ 测试框架与 CTest 注册方式：`docs/contracts/testing.md`。
- 跨平台依赖版本、构建和发现策略：`docs/contracts/dependency-lock.md`。
- 剪映兼容默认快捷键及平台映射：`docs/contracts/shortcut-map-macos-windows.json`。
- 文件所有权、公开接口和禁止跨层访问：`docs/contracts/implementation-file-ownership.md`。
- 全局约束：`AGENTS.md`。
- 本索引不接受已删除的 Electron/TypeScript 代码作为实现来源。

所有计划中的 `void test...()` 代码块都是 QtTest `QObject` 测试类的 `private slots` 方法体；测试文件骨架、`QTEST_MAIN`、CMake/CTest 注册和异步等待方式必须逐字遵从 `docs/contracts/testing.md`。00 的合同校验可额外使用 CTest 注册的 `cmake -P` 脚本；它不引入第二套 C++ 测试框架。

每个任务的五个复选步骤按固定顺序执行：写失败测试、运行并确认失败、最小实现、重跑并确认通过、提交。已使用简写的模块计划仍严格按这一顺序解释；新增任务必须显式标出 `Step 1` 至 `Step 5`。

## 不实施的服务端范围

支付、订阅、设备、验证码、资源审核的生产服务端不属于 0.2.0 主 App 实施范围。客户端仍必须实现签名目录的 schema/验签/缓存/失败态、验证码与账户 UI、两小时离线状态和触发云端 AI 时的订阅状态检查边界；不得伪造成功、审核或在线状态。

## 环境门

实施前必须由开发者按 `docs/contracts/dependency-lock.md` 与 `docs/installation/2026-08-11-edward-0.2.0-developer-environment.md` 完成固定版本的 CMake、Ninja、Qt 6、MLT、GPL FFmpeg 和 nlohmann-json 安装，并在 macOS 与 Windows 通过阶段 01 的 CMake 依赖发现。05 前还必须关闭 G-01 字体工件门；06 前关闭 G-02 `large-v3-turbo` 模型工件门；07 前关闭 G-03 硬件质量门；08 前关闭 G-04 Windows 同 MSVC 媒体前缀门。
