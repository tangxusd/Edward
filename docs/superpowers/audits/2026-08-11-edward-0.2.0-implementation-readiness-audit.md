# Edward 0.2.0 实施计划可执行性审计

**日期：** 2026-08-11（Asia/Shanghai）

**范围：** 权威规格、最终视觉确认稿、00–08 模块计划、依赖/测试/渲染/标题栏合同。
**审计方法：** 只以最终视觉表格、权威需求 ID、计划任务文件清单、任务步骤和真实本机依赖探测为证据；不以已删除的 Electron/TypeScript 代码推断实现。

## 初始结论：计划不可直接进入实施

设计方向、模块顺序和 macOS 运行时依赖已经具备基础，但以下 P0 会导致第一位执行者无法按计划稳定开始，或导致高风险功能遗漏。必须先修复计划本身，再开始 C++/QML 实现。

| 编号 | 根因证据 | 影响 | 修复原则 |
| --- | --- | --- | --- |
| P0-01 | 00 的四个任务要求运行 `ctest --preset macos-debug`，但创建 `CMakeLists.txt`、预设与 CTest 注册的动作排在 01-1。 | 00→01 的第一条失败测试没有可执行宿主，阶段顺序自相矛盾。 | 在 00 先建立仅用于合同校验的 CMake/CTest 引导器；01 只扩展该引导器为应用目标。 |
| P0-02 | 02-2 用一条“实现”同时覆盖插入、覆盖、波纹删除、分割、多选、分组、链接、轨道状态、源/工程入出点、循环、变速、倒放、定格等。 | 无法独立拒绝或验收任何一种编辑行为；遗漏会被“命令历史通过”掩盖。 | 按数据不变量拆为放置、裁剪/变速、选择/轨道状态、编辑模式、历史、播放/标记/快捷键六个可测试任务。 |
| P0-03 | 03–08 多处使用 `headers`、`implementations`、`tests`、`{a,b}` 或 `controller.*`，且 17 个任务缺少显式 Step 3 或 Step 4。 | 文件归属、接口名称、失败测试和验证命令无法由零上下文执行者确定。 | 冻结路径所有权与公开接口目录；所有任务显式具有 Step 1–5，且每项只交付一个可拒绝的功能切片。 |
| P0-04 | 最终视觉基线使用内置字体回退，但没有可再分发字体工件、许可证、版本、哈希或 Windows/macOS 同一回退文件。 | 05 的跨平台截图门无法在字体一致性上复现。 | 作为 05 前的 G-01 工件门保留；未取得实际字体文件和 SHA-256 前不开始截图基线生成。 |
| P0-05 | `large-v3-turbo` 工件尚不存在；Windows MSVC 媒体前缀、硬件编码质量报告也尚无实机证据。 | 06、07、08 不能假定通过。 | 保留为 G-02/G-03/G-04；不得用小模型、未测硬件或 MinGW 替代。 |

## 本轮允许修复范围

- 修复 P0-01 至 P0-03 的**计划与合同**，使 00–08 的启动顺序、文件所有权、接口和验收颗粒度一致。
- P0-04/P0-05 只记录为不可替代的外部阶段门；不在没有工件或实机的情况下声称关闭。
- 不创建应用源码、CMake 工程、字体二进制、模型二进制、Windows 产物或服务端。

## 重新准入标准

1. 00 的每个 CTest 命令都由 00 创建的引导器注册；01 不再重复创建同一引导器。
2. 02 的所有 TL-01 至 TL-08 子能力各有明确任务、文件、接口和单独 CTest 名称。
3. 00–08 的任务均显式列出 Step 1–5，且源/头/测试路径无通配或 brace shorthand。
4. 47 条权威需求 ID 与 44 条最终视觉 Route 仍有唯一模块验收责任。
5. G-01 至 G-04 明确保留，不以文档更新代替工件、硬件或 Windows 实测。
