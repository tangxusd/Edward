# Edward 0.2.0 阶段门回溯审计

**审计日期：** 2026-08-11（Asia/Shanghai）

**审计范围：** 已冻结的 0.2.0 需求台账、权威追溯矩阵、视觉确认稿、视觉 Route 基线、00–08 详细计划、依赖合同、开发环境实测结果。
**不在范围：** 已明确延后的资源生成专用 App、订阅/支付/设备/验证码后端、资源审核后端的服务端实现；它们仍须在发布前具备真实服务，不能以客户端假成功替代。

## 结论

**当前不应直接进入应用代码实施。** 设计的功能范围已较完整，且 macOS 本地环境的 Qt 6.11.1、FFmpeg 8.1.2、MLT 7.40.0 已核验可用；但仍有 8 个 P0（会使不同实施者产出不一致、错误保存数据、错误色彩或无法建立真实能力）和 7 个 P1（会显著影响跨平台一致性、质量验证或后续集成）需要先收敛到合同文件。

这不是要求降低功能范围。所有问题都应通过补齐明确合同、依赖和验证夹具解决。

## P0：必须在开始应用代码前解决

### P0-01：最终视觉清单引用了不存在的时间线主稿

- **冲突：** 视觉确认稿把 `edward-shotcut-timeline-v4-aligned-header.html` 作为工作台时间线的唯一覆盖稿，并在“自检”中声称全部存在；该文件在 `.superpowers/brainstorm/19764-1786246498/content/` 中不存在。视觉 Route 基线也未为它建立路由。
- **影响：** 05 实施者无法知道工作台的底部时间线应以哪个像素基准实现，且清单的完整性断言为假。
- **涉及：** `docs/superpowers/specs/2026-08-10-edward-0.2.0-visual-confirmation-manifest.md` 的“覆盖与禁止事项”；`docs/contracts/visual-route-baseline.md`。
- **必须修复：** 恢复该最终 HTML 并加入 Route 基线，或明确改为由 `edward-workbench-v19-0.2-fixed.html` 的内嵌时间线作为唯一基准并删除失效覆盖引用；两处必须同步。

### P0-02：存在第二份可执行核心计划，可能与 00–08 重复实施

- **冲突：** `2026-08-10-edward-0.2.0-core-engine.md` 含 Task 1–6、失败测试、提交命令和 `Execution Handoff`，但没有“已废弃/不得执行”标识；00–08 索引未引用它。
- **影响：** 任何按文件名或全文搜索执行的 agent 都可能先按旧 Task 1 建骨架，导致目录、合同和测试与 00–08 分叉。
- **必须修复：** 保留文件历史内容，但在标题下添加显眼的“非执行/已由 00–08 取代”说明，或移动到历史目录；执行入口只能为 `2026-08-11-edward-0.2.0-plan-index.md`。

### P0-03：工程持久化边界未形成无歧义 Schema

- **冲突：** 权威规格 PRJ-04 明确轨道状态、时间线视图状态和播放头不写工程；00 计划却把通用 `uiState` 作为 `ProjectDocument` 字段；台账第 3 节与第 14.1 节又写“UI 状态”在项目目录/工程中。台账第 37、40 条要求参考线和标记保存，第 41、42 条要求轨道状态、缩放、滚动、播放头不保存。
- **影响：** 不能安全冻结 `project.json`；实施者可能错误保存临时视图状态，也可能丢失应恢复的参考线、标记或 AI 会话。
- **必须修复：** 将 `uiState` 拆为命名明确的持久化字段（例如 `guides`、`markers`、`aiSessions`）与明确不落盘的会话状态（选中项、轨道锁定/静音/隐藏/独奏、滚动、缩放、播放头）。工程 Schema 禁止通用、自由扩展的 `uiState`。

### P0-04：色彩转换与“原始字节副本”语义冲突

- **冲突：** PRJ-01 要求导入只复制原始字节、副本不重编码；ARC-03 和 00 计划表述“导入不同色彩空间时转换到 Rec.709”。
- **影响：** 可能出现导入阶段毁损源副本、重复占用磁盘，或预览/导出使用不同色彩解释；这是画质和可恢复性的核心风险。
- **必须修复：** 冻结为“`media/` 永远保存原始字节副本；探测所得色彩元数据与 Rec.709 转换参数进入不可变 RenderGraph；代理可使用派生转换文件；导出按 RenderGraph 转换。若无法建立正确转换，创建/导出失败且提示”。同时在颜色夹具中覆盖 SDR、HDR、错误/缺失元数据。

### P0-05：RenderGraph 没有冻结预览合成边界，不能证明预览与导出一致

- **缺失：** 04 计划说 MLT 消费 `ProjectSnapshot`，QML 预览还需承载组件选择、节点编辑、拖拽和缩放；但没有规定组件/字幕/文字节点究竟由何处光栅化、如何与 MLT 视频帧在同一颜色空间和同一帧时间合成、以及预览交互覆盖层如何回写为引擎命令。
- **影响：** 最容易产生“预览看到的组件/字体/关键帧与导出不同”的架构缺陷，违反单一 RenderGraph 目标。
- **必须修复：** 00 的 `render-graph.md` 必须定义：统一场景图、文本/组件渲染后端、MLT 图层边界、QML 仅交互命中与控制框叠层、帧编号/坐标/颜色空间转换、离屏渲染比较方法。没有该合同不得实现预览窗。

### P0-06：本地转写与时间戳对齐没有可实现的运行时合同

- **缺失：** CRT-03 要本地中英文转写、Markdown 和时间戳对齐；06 计划仅列 `transcription.cpp`，没有指定模型/运行时、语言模型版本与许可证、CPU/GPU 路径、模型分发、时间戳格式、失败条件、质量夹具或对齐算法。
- **影响：** 新建项目的 AI 初版、字幕轨和语义文本均无法真实实现，容易被错误地替换成占位实现。
- **必须修复：** 在依赖合同锁定一个可商用 GPL 兼容的本地转写运行时及模型清单，明确中英文检测、分段/标点、帧时间基准、失败恢复与两台基准机夹具。此项需要先进行技术选型，不允许用假转写通过测试。

### P0-07：文稿格式支持没有解析依赖或安全合同

- **缺失：** CRT-02 要 TXT、Markdown、DOCX、可复制文本 PDF、SRT；现有计划只有功能描述。依赖锁定中没有 DOCX 容器/XML 解析器、PDF 文本提取库，也没有文件大小、编码、损坏文件、宏/外链禁止规则。
- **影响：** 创建流程无法按已确认格式真实导入；随意引入库会破坏跨平台与许可证一致性。
- **必须修复：** 为 DOCX 与文本 PDF 选定 GPL-compatible 跨平台库或明确的受控解析实现，锁定版本、许可证、输入边界和测试样本；扫描 PDF 必须稳定返回“不支持 OCR”的可见结果。

### P0-08：真实网络、签名验证和受限插件缺少基础依赖与宿主协议

- **缺失：** 06 要调用 Responses/Chat Completions、读取 Supabase/GitHub 目录并以 Ed25519 验签，但锁定 Qt 模块未包含 `Network`，依赖表也没有具体 Ed25519 实现。插件规则同时要求“无网络直连”，但用户已确认 Remotion/Hyperframes 在线运行；台账说明应由 Edward 宿主代理，计划未定义允许的代理请求、域名白名单、凭证隔离、文件传输和错误码。
- **影响：** 模型、资源、订阅验证与插件都不能安全地做成真实调用；直接让插件联网或给它工程写权限将违反已确认隔离边界。
- **必须修复：** 在 00/06 增加网络与密码学依赖合同，以及受限插件宿主 RPC：插件只向宿主请求经批准的操作；宿主持有网络与凭证、按 manifest 能力/域名白名单转发、将输入输出写入临时隔离目录，绝不暴露工程写权限或模型密钥。
