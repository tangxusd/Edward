# Orbit 颜色、字体、偏好与管理后台设计

## 状态

- 状态：设计已确认，等待实现计划
- 范围：颜色模块、字体模块、默认偏好、兑换码、邀请码、时间线交互、循环动画、Supabase 管理能力和 `admin.edward.uno` 管理后台
- 产品：Orbit（原 Edward）
- 原则：Supabase 是云端事实源；Orbit 本地缓存是编辑会话事实源；项目文件保存已应用的具体值，不依赖在线目录

## 1. 目标与拆分

五个子项目共同推进，但共享一套数据合同和版本规则：

1. 颜色与字体模块：独立目录、缓存、安装、预览和偏好桥接。
2. 新用户默认偏好、兑换码和邀请码奖励。
3. 播放头交互、逐帧定位和循环动画方向。
4. Supabase 管理数据、管理员权限、审计和统计。
5. `admin.edward.uno` 管理后台。

每个子项目都必须可以单独测试和回滚；不得把后台写权限、在线目录访问或字体安装逻辑塞进项目文件或组件运行时。

本方案扩展现有 `preference_facts`、`subscription_rules`、`referrals` 和 `credit_ledger`，不得创建同义的第二套事实表。新增 migration 必须保持现有字段、RLS、幂等键和历史数据兼容；需要改变语义时先增加版本字段和迁移适配器，再切换客户端。

## 2. 总体架构

```text
Supabase
├─ color_catalog / font_catalog / default_preference_profiles
├─ preference_facts
├─ redeem_codes / redeem_code_redemptions
├─ referrals / credit_ledger / referral_rules
├─ admin_roles / admin_audit_events
└─ Edge Functions：所有写操作、权益、兑换、奖励、后台管理

Orbit 桌面端
├─ ColorPresetModule
├─ FontCatalogModule
├─ PreferenceStore
├─ TimelineInteractionModule
├─ AnimationEvaluator
└─ Preview / Render / Export 共用规范化属性数据

admin.edward.uno
└─ Refine 管理 UI → 管理 Edge Functions → Supabase
```

Refine 只负责管理界面、资源列表、筛选、表单、权限路由和统计图表。它不能持有 `service_role`，不能直接绕过 Edge Functions 修改业务表。管理员身份同时由 Supabase 登录会话和 `admin_roles` 服务端记录决定。

所有客户端和后台写操作都必须使用版本化 JSON 合同，并带 `requestId`。Edge Function 负责鉴权、输入校验、幂等、事务和审计；RLS 负责最后一道数据边界。客户端永远不能提交 `user_id`、管理员角色、订单金额、权益状态、奖励余额或目录发布状态。

## 3. 颜色模块

### 3.1 统一颜色来源

属性检查器中的文字、线条、边框、背景、阴影、SVG `fill`、SVG `stroke` 和组件声明的颜色属性全部通过 `ColorPresetModule` 提供。模块输出：

```text
colorPresetId
colorValue
colorSpace
alpha
catalogRevision
source
preferenceSubject
```

颜色目录只负责提供可选值和元数据，项目实例保存用户实际应用的色值快照。历史项目不引用未来目录 ID，因此目录更新不会改变历史项目。

### 3.2 读取与缓存

进入项目时先读取本地缓存，然后最多发起一次目录版本检查和必要的增量同步，建立项目会话快照；项目会话内属性检查器、预览、渲染和导出只读取本地缓存和会话快照。网络不可用时使用上一次有效缓存，完全没有缓存时使用内置安全默认值。

缓存键至少包含 `accountId`、`installationId`、`catalogType` 和 `catalogRevision`。登录用户切换、退出登录、缓存哈希不匹配或目录合同升级时，旧缓存只能作为离线只读回退，不能跨账号复用。项目关闭不会删除缓存；用户主动退出账号时清除账号关联的会话快照。

本地缓存必须有容量上限、最近使用时间和可恢复清理策略：优先清理已废弃且未被项目引用的目录和字体预览资源，完整字体只有在没有项目引用且用户主动卸载时才能清理。清理失败不能删除项目仍在使用的文件。

后台发布目录新版本后，不打断当前项目。用户下次进入项目时比较 `catalogRevision`，通过内容哈希验证后更新缓存。缓存更新不回写已有片段。

增量包必须包含父版本、目标版本、文件哈希和删除列表；增量校验失败时丢弃临时包并重新请求完整目录，不能拼接未经校验的目录。

客户端目录接口固定为：

```text
getCatalogManifest(catalogType, knownRevision) -> { revision, fullHash, delta, expiresAt }
downloadCatalogDelta(catalogType, parentRevision, targetRevision) -> verified package
getFontAsset(fontId, version, contentHash, purpose=preview|install) -> short-lived URL
```

接口只返回已发布版本；草稿、撤回版本和未通过授权校验的资源不能被客户端读取。Orbit 记录 `lastSyncAttempt`、`lastSyncSuccess` 和错误原因，避免每次进入项目重复重试导致网络请求风暴。

### 3.3 颜色目录合同

每个颜色目录项至少包含：

```text
colorPresetId
name
category             # text / line / border / background / shadow / svg / component
value                # 规范化颜色值
colorSpace           # srgb 或项目明确支持的空间
alpha
tags
status
version
contentHash
```

服务端拒绝非法颜色空间、透明度、重复 ID 和不匹配的版本哈希；客户端只把通过合同校验的项放入缓存。

目录表至少分为 `color_catalog_revisions` 和 `color_catalog_items`；项目发布只引用不可变 revision，草稿修改不得改变已发布 item。颜色目录 Storage 不保存项目私有色值，用户自定义色值仍由本地偏好事实保存。

## 4. 字体模块

### 4.1 字体目录和文件

字体目录包含：

```text
fontId
familyName
displayName
version
fileFormat
fileSize
contentHash
licenseStatus
entitlement
fallbackFamilies
catalogRevision
```

字体文件存储在 Supabase 私有 Storage，只能由服务端返回短时签名地址。客户端下载后先校验大小、格式、内容哈希和授权状态，再写入用户本地字体缓存和用户字体目录。安装失败必须明确提示，不得静默替换字体。

目录表至少分为 `font_catalog_revisions` 和 `font_catalog_items`，完整字体文件、预览字体文件和授权证明使用独立 Storage 对象；数据库只保存对象键、哈希和版本，不保存公开下载 URL。每个版本必须声明支持的平台和字体格式。

安装只写用户级字体目录，不修改系统字体目录，不要求管理员权限。安装路径和临时下载路径必须由 Orbit 生成并限制在字体缓存根目录内，禁止使用目录元数据中的任意路径。字体格式、最大文件大小、字体表结构和授权范围由服务端目录合同固定；字体文件不能包含可执行入口。

### 4.2 用户选择后的安装流程

字体只在用户明确选择或点击下载后下载和安装，不在项目进入时下载全部字体：

```text
字体列表预览
→ 用户选择/点击下载
→ 获取短时签名地址
→ 下载到临时缓存
→ 校验格式、大小、哈希和授权
→ 安装到用户本地字体目录
→ 刷新字体运行时
→ 写入项目字体快照和偏好事实
```

安装过程使用临时文件和原子重命名；同一 `fontId + version + contentHash` 并发下载只允许一个任务写入。卸载或替换字体前必须检查项目引用，历史项目引用的字体不得被自动删除。字体更新只新增版本，不覆盖旧版本。

安装完成后由字体运行时适配器刷新浏览器字体集合和导出字体集合：预览侧使用受控 `@font-face`/`document.fonts.load`，导出侧使用同一 `fontCacheKey` 解析到本地字体文件。两侧都必须回读字体实际加载状态；只写入文件但未加载成功不能标记为已安装。

字体安装由平台适配器实现：macOS、Windows 和 Linux 使用各自的用户级字体目录、刷新机制和权限检查；公共合同不暴露平台路径。字体显示名必须映射到 Orbit 生成的唯一内部 family 名，避免不同字体包伪造同名 family 互相覆盖。

### 4.3 字体列表 UI

列表按字体自身渲染字体名称，提供：

- 已安装/下载按钮和状态；
- 收藏星标；
- 资源权限标记；
- 下载进度和失败重试；
- 当前选择状态。

项目记录：

```text
fontId
fontFamily
fontVersion
fontFileHash
fontCacheKey
fallbackFamily
```

本地绝对安装路径只保存在设备缓存索引，不写入项目文件，避免项目换设备后失效。历史项目继续使用已安装并记录哈希的字体；目录下架或新版本发布不会自动替换历史项目字体。

项目在其他设备打开时，如果 `fontFileHash` 不存在：

```text
提示缺少字体
→ 用户主动下载并安装相同版本
→ 校验 hash 后恢复预览/渲染/导出
```

在用户未确认下载前，项目保持缺字状态提示，不得静默改用其他字体并声称结果一致。用户选择回退字体后，必须作为一次明确的项目属性修改记录。

### 4.4 未安装字体的预览

未安装字体也必须能在下拉列表中真实预览。目录为每个字体提供经过授权的轻量预览字体或预览资源：

```text
previewFileHash
previewFileFormat
previewFileSize
previewSampleText
```

预览资源与完整安装字体分别校验和缓存；预览资源不能被当作完整字体安装。只有用户确认选择后才下载完整字体文件。需要授权的字体在预览前显示权限状态，未授权用户不能取得完整字体签名地址。

字体安装需要用户明确同意该字体的授权条款；授权状态变化只影响新的下载和安装，不自动删除已安装文件或篡改历史项目。

## 5. 偏好系统和默认偏好

### 5.1 会话缓存

缓存分三层：

```text
内置安全默认值 → 用户本地目录缓存 → 当前项目会话快照
```

项目进入时只同步一次颜色/字体目录。后续属性选择、预览、渲染和导出全部访问缓存，不在每次操作时访问 Supabase。

### 5.2 首次安装默认偏好

Supabase 维护版本化默认偏好。默认偏好只在以下条件同时满足时使用：

1. 当前安装实例尚未建立本地用户偏好；
2. 用户首次创建或打开项目；
3. 当前属性没有用户 A/B/C 或确认过的单属性值。

默认值应用不产生学习事实，也不覆盖已有用户方案。用户明确确认颜色、字体或其他属性后，才写入 `property` 事实并开始收敛 A/B/C。

本地保存 `defaultBootstrapVersion` 和 `firstProjectOpenedAt`，保证默认偏好只初始化一次。用户登录后如果云端已有事实，先合并事实再应用默认值；云端默认偏好更新不会重新初始化已经完成过首次安装的本地实例。

### 5.3 统一读写边界

`PreferenceStore` 是唯一偏好写入方。颜色模块和字体模块只提交经过合同校验的确认事实；项目文件只保存实际应用值和资源快照，不保存偏好方案本身。

颜色和字体确认事实必须使用稳定的偏好身份键，不能只记录显示名称：

```text
preferenceSubject = color | font
semanticPath
propertyPath
valueType
value
catalogRevision
resourceVersion
contentHash
source = user-confirmed | ai-confirmed | default-applied
```

`default-applied` 永远不参与收敛；颜色事实保存规范化具体色值，字体事实保存 `fontId + version + contentHash`。同一个字体名称或颜色名称在不同版本中不能被模糊合并。

偏好事实仍遵循显式同步规则：本地确认先写入 `PreferenceStore` 和可恢复队列，云端上传只在用户主动同步、登录后合并、切换账号或既定后台同步窗口触发；项目会话内不因颜色/字体选择直接请求 Supabase。上传使用 `eventId` 幂等合并，下载事实必须重新经过目录合同和属性合同校验，失败事实隔离并显示诊断，不影响编辑。

## 6. 兑换码

### 6.1 数据和安全

新增：

- `redeem_code_batches`：批次、套餐、时长、数量、创建者、生成时间；
- `redeem_codes`：代码哈希、批次、有效期、状态、使用者、使用时间；
- `redeem_code_redemptions`：用户、代码、订单/权益、请求 ID、结果、时间。

兑换码采用服务端随机生成，数据库只保存带密钥的 HMAC/哈希、批次、套餐、时长、有效期和状态。明文兑换码只在生成响应中展示一次，不写日志、不写前端持久化存储。兑换码默认有效 24 小时，数据库使用唯一约束和幂等请求 ID 防止重复兑换。批次生成必须限制数量、速率和总面值，并记录管理员审计摘要。

### 6.2 客户端流程

订阅/续订面板右上角增加“兑换码”小字按钮：

```text
输入兑换码
→ Edge Function 验证 JWT、哈希、有效期、状态和风控
→ 原子创建月度/季度/年度权益
→ 写入兑换记录和审计记录
→ 返回新的权益状态
```

客户端不能提交或修改套餐、时长、金额和权益状态。

兑换必须在同一数据库事务内完成“锁定代码 → 校验用户 → 创建权益/订阅周期 → 写入兑换记录 → 标记已使用”。任何一步失败都回滚；重复请求只能返回第一次成功结果，不能重复延长权益。

跨表兑换、奖励和订阅周期变更必须通过 Supabase Postgres RPC/事务函数完成，Edge Function 只负责鉴权、速率限制和调用 RPC；不能依赖多次独立 REST 写入来声称原子性。

兑换码批次必须保存 `currency`、`entitlementType`、`durationMonths`、`ruleVersion` 和 `effectiveAt` 快照。兑换只能创建服务端支持的月度、季度或年度权益；不能通过代码传入任意天数、价格或套餐字段。

权益生效规则固定为：未过期权益从当前 `current_period_end` 顺延，已过期权益从服务端当前时间开始；兑换不得改变已支付订单金额、退款状态或自动续订绑定。兑换产生的权益周期必须可在订阅面板和后台审计中追溯到兑换记录。

## 7. 邀请码和邀请奖励

订阅/续订面板右上角增加橙色“邀请码”按钮，显示用户专属邀请码和邀请链接。

后台规则控制：

```text
allow_unsubscribed_inviter
reward_amount
max_credit_per_order
credit_valid_days
eligibility_requirements
```

被邀请用户完成注册、邮箱验证并成功订阅后，服务端只发放一次不可提现奖励。奖励进入不可变 `credit_ledger`，可在下次续费抵扣，不可兑现、转赠或由客户端修改。退款、拒付和风控命中时奖励冻结或撤销。

邀请链接只允许在注册事务中绑定一次；禁止自邀、循环邀约、已存在账号重复绑定和同一支付订单重复奖励。奖励事件使用 `referredUserId + qualifyingOrderId` 唯一键幂等，后台修改规则不追溯已发放账本记录。

邀请链接只携带不可推断用户身份的短 token；注册前只记录匿名点击事件，注册后才绑定用户 UUID。点击日志必须限流、去重并设置保留期限，不能用 IP 或设备指纹作为奖励资格的唯一依据。

奖励和抵扣使用订单币种的最小货币单位，规则版本和抵扣上限写入订单快照；抵扣顺序固定为“原价 → 套餐折扣 → 邀请抵扣”，余额不足时只抵扣实际应付金额，剩余余额继续保留但不可提现。

## 8. 播放头和时间线交互

- 播放头颜色固定为 `#6CFF37`；
- 播放头分割线宽度为 `1px`；
- 鼠标进入轨道区域播放头线的命中范围时显示拖拽光标；
- 拖拽按时间轴像素换算为项目帧，并以帧边界吸附；
- 空白轨道单击直接把播放头定位到鼠标位置；
- 左右键按项目帧率精准移动一帧；
- 预览、时间线和导出统一使用 `state.time` 的帧值，避免秒/帧漂移。

拖拽和单击都使用时间线内容区的实际 `getBoundingClientRect`、缩放比例和滚动偏移计算帧值；不使用窗口坐标或固定像素比例。拖拽使用 Pointer Capture，离开轨道仍可连续移动；播放中拖拽时先暂停，完成后按原播放状态恢复。左右键只在时间线或播放头拥有焦点时生效，避免修改文本输入框。

空白定位只在未命中片段、轨道控制、标记或工具按钮时触发；命中片段时保留片段选择语义，命中标记时保留标记选择和右键菜单语义。拖拽命中阈值、最小可拖动距离和帧吸附规则必须在预览缩放变化下保持一致。

## 9. 循环动画

循环动画新增方向枚举：

```text
right
left
up
down
scale-up
scale-down
```

动画数据保存为规范化参数和关键帧，不保存渲染结果。求值器必须同时被预览、离线渲染和导出调用：

```text
direction + distance/scale + durationFrames + easing + loopMode
```

方向与属性映射固定：`right/left` 写入 `x`，`up/down` 写入 `y`，`scale-up/scale-down` 写入 `scale` 或组件声明的等价缩放属性。`loopMode` 至少区分 `repeat` 和 `ping-pong`，循环边界按整数帧计算，避免浮点累计误差。动画合同必须记录属性路径、起止值、持续帧数、缓动和版本；没有声明对应属性的组件拒绝该动画。

方向坐标以画布中心为原点，`x` 向右为正，`y` 向上为正；持续缩放以组件当前有效尺度为基准，不重置用户已确认的初始值。循环动画必须规定首帧、末帧和循环衔接帧，确保预览和导出不会出现一帧跳变。

超出组件支持范围、属性未声明或关键帧非法时阻断执行并报告原因。

导出前必须对动画合同重新校验：属性映射、关键帧数量、持续帧数、缓动名称和循环边界全部通过后才允许进入渲染队列；预览中可显示但导出不支持的动画不得被标记为成功，必须明确列出阻断字段。

## 10. 管理后台

### 10.1 管理范围

统计：

- 用户总数和增长；
- 订阅、续订、到期、退款；
- 意见反馈和问题日志；
- 兑换码生成与使用；
- 邀请关系和奖励记录。

管理：

- 颜色目录和版本发布；
- 字体目录、字体文件和授权状态；
- 默认偏好；
- 大模型模板；
- 兑换码批次生成；
- 邀请规则和奖励金额；
- 用户状态和人工处理记录；
- 管理员角色与审计日志。

颜色、字体和默认偏好目录使用统一的发布状态机：

```text
draft → validated → staged → published → deprecated → rolled_back
```

每次发布必须生成不可变 `catalogRevision`、完整哈希、父版本、变更摘要和操作者审计。发布前检查资源文件、合同、授权、增量包和回滚包；撤回或回滚只影响后续项目会话，不修改当前会话和历史项目。

统计和处理所需的业务数据必须有明确的服务端合同：

- `feedback_items`：用户、类别、内容摘要、状态、处理人、时间；
- `problem_logs`：请求 ID、客户端版本、错误分类、脱敏摘要、时间和处理状态；
- `llm_templates`：模板 ID、模型、版本、内容哈希、状态、生效区间和审计信息；
- 统计视图：只输出计数、趋势和脱敏聚合，不直接暴露支付响应、邮箱全文或签名地址。

反馈内容和问题日志必须在写入前做长度限制、敏感字段过滤和用户可见范围控制。

统计数据保留期限、删除规则和聚合粒度由后台规则版本化；原始问题日志和反馈不得无限期保留。管理员查看用户明细时必须记录查看事件，导出统计默认只允许聚合数据。

### 10.2 权限

新增：

- `admin_roles`：用户 UUID、角色、状态、生效时间；
- `admin_audit_events`：管理员、动作、目标、前后摘要、请求 ID、时间和结果。

初始管理员为 `tangxu8@icloud.com` 对应的 Supabase 用户，但生产授权以用户 UUID 和 `admin_roles` 为准。邮箱本身不能作为唯一授权条件。

初始化迁移不得把邮箱字符串当成永久管理员判断；首次部署时由受保护的 bootstrap Function 查询已验证邮箱并写入用户 UUID，之后所有请求只查 `admin_roles`。管理员会话需要短期 JWT、刷新令牌轮换和强制重新验证高风险操作；角色变更、用户状态修改、兑换码批量生成和奖励规则变更必须二次确认并写审计。

### 10.3 部署

后台部署到 Cloudflare，域名为 `admin.edward.uno`。部署产物只包含公开 Supabase URL、anon key 和前端资源；前端不嵌入 service role。敏感配置只放 Cloudflare/Functions 环境变量。后台每个写操作都经过 Edge Function 的管理员校验、输入合同、幂等处理和审计记录。Cloudflare 部署使用独立的 admin 项目和预览环境，生产发布必须通过构建检查、Supabase migration 检查和域名健康检查。

统计页面读取只读聚合视图或统计 Function，不直接扫描明细表；用户邮箱、支付响应、兑换明文和字体签名地址不得进入浏览器日志或统计结果。管理后台访问失败不能影响 Orbit 桌面端编辑和导出。

后台登录页必须使用 Supabase Auth，登录成功后由服务端查询 `admin_roles`；前端隐藏菜单不构成权限控制。会话过期、角色撤销或账号禁用时，Edge Function 立即拒绝后续请求。Cloudflare 日志和前端埋点不得记录 access token、refresh token、兑换明文或字体签名 URL。

管理 Edge Functions 只接受 `https://admin.edward.uno` 的允许来源，并校验 CSRF/请求关联 ID；CORS 允许列表不能使用通配符。高风险操作要求重新验证管理员会话，批量操作必须支持预览、确认、取消和结果下载，避免误发布或误生成兑换码。

## 11. 错误、缓存和兼容

- 颜色或字体目录同步失败不影响已有项目编辑；
- 字体下载或安装失败不得修改当前项目属性；
- 缓存损坏时隔离损坏条目并回退内置默认值；
- 目录更新不改写历史项目；
- 兑换和奖励失败必须保持事务原子性；
- 管理后台只能看到经过聚合或授权的用户数据；
- 预览、渲染、导出使用同一快照和求值器；
- 目录缓存、字体安装、兑换和奖励操作均有可恢复的状态机和请求 ID；
- Supabase migration 必须先添加结构和 RLS，再发布 Function，最后切换客户端目录版本；
- 跨表权益、兑换和奖励只能由事务 RPC 写入，Edge Function 不得用多次独立写入模拟事务；
- 不引入 Component IR 或新的组件转换层。

## 12. 验收标准

1. 项目进入时只进行一次颜色/字体目录同步检查，项目会话内不重复访问 Supabase。
2. 颜色块覆盖文字、线条、边框、背景、阴影、SVG 和组件颜色属性。
3. 字体列表以字体自身渲染名称，用户明确选择后才下载、安装并可用于预览/渲染/导出。
4. 历史项目保存具体色值和字体文件哈希，目录更新不改变历史结果。
5. 默认偏好只在首次安装且没有用户方案时生效，不计入学习事实。
6. 兑换码 24 小时有效、单次兑换、可追溯且不能由客户端伪造权益。
7. 邀请奖励遵循后台规则，进入不可变抵扣账本，支持冻结、撤销和审计。
8. 播放头颜色、拖拽、空白定位和左右键逐帧操作可验证。
9. 六类循环动画方向在预览、渲染和导出中结果一致。
10. `admin.edward.uno` 使用 Refine，所有管理写操作经过管理员 Edge Function 和审计。
11. `tangxu8@icloud.com` 登录后只有在 `admin_roles` 授权时才具备管理员权限。
12. 增量目录包父版本、哈希和删除列表校验失败时不会污染本地缓存。
13. 字体只安装到用户级目录；历史项目引用的字体版本不会被自动删除或替换。
14. 兑换码重复请求、并发兑换和权益创建失败均保持幂等和事务回滚。
15. 邀请关系只能绑定一次，奖励按被邀请用户和成功订单唯一发放，退款可冻结或撤销。
16. 时间线缩放、滚动、拖拽、播放状态和帧率变化下，播放头定位仍以整数帧为准。
17. 管理后台统计不暴露明细敏感字段，管理员高风险操作可追溯到用户 UUID、请求 ID 和审计事件。
18. 颜色和字体确认事实包含稳定身份键、目录版本和内容哈希，默认应用事实不参与收敛。
19. 字体安装成功必须同时通过本地文件校验和预览/导出运行时回读；缺字时不会静默替换。
20. 兑换码批次保存币种、权益类型、时长和规则快照，不能通过兑换请求注入任意权益。
21. 播放头空白定位不会抢占片段、标记和轨道控制的点击语义。
22. 动画方向、坐标、循环边界和缩放基准在预览与导出中一致。
23. 原始反馈和问题日志有版本化保留与删除规则，管理员明细访问可审计。
24. 目录接口只返回已发布版本，目录发布、撤回和回滚均生成不可变 revision 和审计记录。
25. 项目会话内不因颜色/字体选择直接访问 Supabase，偏好事实通过本地可恢复队列显式同步。
26. 兑换权益对未过期订阅顺延、对已过期订阅从服务端当前时间起算，且不改变支付订单。
27. 后台角色撤销或会话过期后，Edge Function 立即拒绝管理请求；敏感令牌和签名地址不进入日志。
28. 导出前重新校验动画合同，任何预览/导出不一致都会阻断导出并报告字段。
29. 新 migration 不复制现有偏好、订阅和奖励事实表，历史数据和 RLS 回归测试通过。
30. 目录和字体缓存有容量上限、引用保护和可恢复清理；平台适配器不把本地绝对路径写入公共合同。
31. 兑换、订阅周期和奖励跨表变更通过事务 RPC 完成，独立 REST 写入无法产生半成功状态。
32. 邀请链接 token 不暴露用户身份，点击日志限流、去重并按保留期限清理。
33. 管理 API 只允许后台来源，CSRF、会话撤销和高风险二次确认均由服务端执行。
