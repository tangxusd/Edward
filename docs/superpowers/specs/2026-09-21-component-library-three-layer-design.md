# Edward 组件库三层资源模型设计

## 目标

统一 Edward 组件库的资源来源、分类、缓存、预览、收藏和插入行为。资源卡片必须保持独立，所有组件均携带 `target` 属性，并通过同一套“添加”和“收藏”操作入口工作。

## 分类模型

### 第一层：资源 Tab

左侧 Tab 是资源类型入口：导入、媒体、文本、音频、卡片及其他既有类型。

- `导入` 只显示用户已经导入当前项目的素材；不读取 Supabase 公共资源。
- 其余 Tab 读取组件库资源。

### 固定筛选

“我的收藏”“最新”“热门”是每个组件库 Tab 的固定筛选，不是第二层分类。

- 进入任意非“导入”Tab 时，默认选中“我的收藏”。
- “我的收藏”显示当前用户收藏的公共资源，并在文本 Tab 顶部固定显示本地的标题和字幕。
- “最新”按资源发布时间倒序。
- “热门”按收藏数量倒序。

### 第二层：业务分类

第二层由 Supabase 资源分类数据驱动，用于承载可扩展的业务分类，例如“标题”“字幕”“矩形”“圆形”“三角形”。固定筛选不会改变组件原有的业务分类。

### 第三层：实际使用来源

第三层描述本次预览、插入或渲染实际采用的来源，不新增左侧导航，也不是公共组件的永久互斥标签：

| 状态 | 含义 | Supabase 行为 |
| --- | --- | --- |
| `local` | Edward 内置的标题和字幕 | 不上传、不拉取更新、不属于公共资源 |
| `cached` | 公共组件已有完整且已校验的本地缓存 | 使用本地可运行包、元数据和低分辨率 MP4；仍可查询远端更新 |
| `remote-preview` | 公共组件没有可用本地缓存 | 从 Supabase 获取元数据和低分辨率 MP4 预览 |

公共组件同时可能具有远端发布版本和本地缓存；使用优先级固定为 `local → cached → remote-preview`。只有 `cached` 或 `local` 可离线插入与渲染。

## 本地固定组件

标题和字幕属于“文本”Tab 的本地隐藏分类：

- 标题默认在画布水平、垂直中心。
- 字幕默认水平居中，位于底部安全区外层虚线以上。
- 它们参与本地缓存、预览、插入和渲染，但不进入 Supabase 上传或更新流程。

## 卡片与预览

卡片正文只显示组件名称。

- 公共组件显示收藏数量。
- 本地组件以“本地”代替收藏数量。
- 不显示摘要、运行时名称、资源来源说明或技术标签。
- 卡片预览为低分辨率、压缩 MP4 小窗口；远端预览从 Supabase 获取，本地缓存组件从本地 MP4 缓存读取，本地固定组件从本地预览来源读取。无可用预览时明确显示无预览状态，不以静态占位冒充视频。
- 预览窗口提供收藏与添加操作。

## 操作与数据流

1. 所有卡片通过统一资源动作接口生成“添加”和“收藏”按钮，保证视觉、事件处理和状态刷新一致。
2. “添加”在当前播放头插入当前组件；组件实例使用自己的资源 ID、`target` 和参数副本，彼此不共享可变状态。
3. 第一次使用公共组件时，将其运行所需包、元数据及低分辨率 MP4 预览写入本地缓存，并标记为 `cached`；后续预览优先读取本地 MP4 缓存。
4. “收藏”调用 Supabase 收藏接口；本地标题和字幕始终可见，不向 Supabase 写入收藏记录。
5. 资源列表先读取本地缓存，再同步远端结果；远端成功后按资源 ID 合并，绝不覆盖本地固定组件。

## Target 合同

每个资源必须有明确 `target`，由资源清单或 Supabase `resources.target` 提供。读取时不得通过运行时名称猜测；缺失 `target` 的远端资源不能插入，并向用户显示中文原因。

`target` 还必须声明能力，例如是否可预览、导出、编辑、带音频或透明通道。插入、预览和导出分别校验相应能力；没有导出能力的组件不得进入项目时间线。

## 发布清单与原生运行时

公共组件版本是不可变发布物，身份为 `component_id + version + content_hash`。每个版本在对象存储中至少包含：

```text
{component_id}/{version}/manifest.json
{component_id}/{version}/package.zip
{component_id}/{version}/preview.mp4
```

`package.zip` 包含运行入口、动画定义和全部依赖资产。清单必须声明：

- `runtime`：仅 `react`、`html-css`、`gsap` 或 `svg`；
- `preview` 与 `render` 原生入口；
- 资产清单：路径、MIME、大小和 SHA-256；
- 作者帧率、总帧数、帧舍入策略；
- 是否允许拉伸、循环或反向播放；
- 静态可编辑属性、可编辑关键帧轨道、只读属性和实例统一属性；
- `target` 与运行能力。

React、HTML/CSS、GSAP、SVG 各自读取其原生动画定义。Edward 不建立或转换为统一动画中间层；清单只定义验证、调用和编辑边界。

## 稳定资源身份与版本升级

`resources.id` 和 `component_id` 是公共组件的稳定身份；`resource_versions` 中的版本和内容哈希是该身份下不可变发布物。收藏、热门统计和分类均关联稳定资源身份，不关联具体版本。

- 同一 `component_id + version` 一经发布，清单、包和 MP4 不得覆盖；修复只能发布新版本。
- 用户项目中的组件实例必须锁定 `resource_id`、`component_id`、`version`、`content_hash`、`target`、实例参数和关键帧覆盖。
- 新版本发布不会影响已有项目。资源库可提示有更新，但只有用户明确执行“升级组件”才迁移实例。
- 升级前必须下载并校验目标版本，保留旧实例快照以供撤销；通过目标组件的原生迁移入口迁移参数和允许编辑的轨道，再用目标 Schema、首帧、中间帧和末帧验证。
- 目标未声明来源版本兼容性、缺少迁移入口、改变 `target`、丢失属性或关键帧时，禁止升级并保留旧实例。
- 已发布包、资产和 MP4 必须长期保留。资源只能标记为 `archived` 或 `withdrawn`，不得物理删除，以保证旧项目可以在新设备复现。

## 时间与组合动画合同

复杂组件可含多个图形、文字、嵌套子组件及依赖资源。组件动画使用作者帧率下的整数帧序号；时间线片段只负责将项目时间映射到组件帧。

- 默认片段时长变化采用等比变速。
- 组件只有在清单声明后才允许循环、反向播放或拉伸。
- 用户关键帧覆盖保存为明确允许的组件帧轨道，不修改组件内部定义。
- 组合内的子元素偏移、父级变换、字体和资产均由锁定版本的原生运行时决定。
- 预览与导出在同一组件帧上必须产生同一画面；发布前须验证首帧、中间帧和末帧。

## 项目实例合同

项目时间线保存组件实例，而不复制或改写组件包。实例只保存锁定版本标识、用户参数、允许编辑的关键帧覆盖和片段时间。

- 用户编辑一个实例不得改变缓存包或其他实例。
- 新版本发布不影响已有项目；只有用户明确升级才迁移实例。
- 位置属性和位置轨道继续使用 Edward 画布中心为 `(0, 0)`、右上为正的坐标合同。

## 属性与关键帧验证

组件清单中的属性定义必须使用 `additionalProperties: false`，并分为：

- `editableProperties`：可编辑静态属性，例如颜色、字体、边框；
- `editableTracks`：允许创建或修改关键帧的轨道；
- `readOnlyProperties`：可显示但不可编辑的版本、作者和时长；
- `instanceProperties`：位置、缩放、旋转、不透明度等统一实例属性。

每项属性定义类型、默认值、范围、步进、单位和 UI 控件。属性检查器、项目保存和运行入口都拒绝未知属性、错误类型、越界值以及不在白名单中的关键帧轨道。

## 本地缓存合同

本地缓存状态为：`未缓存 → 下载中 → 校验中 → 可用 → 已损坏 / 待更新`。

公共组件首次使用时，必须原子缓存完整包、`manifest.json`、所有依赖资产、低分辨率 `preview.mp4` 及校验清单。任一文件缺失或哈希不一致时，组件不可离线使用或预览。

- 已缓存公共组件的资源库预览优先播放本地 MP4。
- 正被当前项目引用的锁定版本不得被缓存清理。
- 离线时仅显示可用缓存组件；远端未缓存组件不能伪装为可插入。
- 远端新版本只标记为待更新，不替换项目正在引用的版本。

## Supabase 数据与对象存储

Supabase 只保存公共组件的发布源、分类、版本、收藏和统计；不保存用户导入素材、本地固定组件或用户的本地缓存文件。

| 数据 | 存储位置 |
| --- | --- |
| Tab 与二级业务分类 | `resource_categories` |
| 公共组件检索元数据、`target`、发布时间与统计 | `resources` |
| 不可变版本、哈希、兼容性和 Storage 路径 | `resource_versions` |
| 组件包、清单、低分辨率 MP4、可选海报 | 私有 bucket `resource-packages` |
| 用户收藏 | `resource_favorites` |

发布器必须将 MP4 写入 `resource_versions.preview_video_path`，不得错误写入 `preview_image_path`。资源查询中，“我的收藏”必须按当前用户的 `resource_favorites` 查询；“热门”严格按 `favorite_count`，且收藏/取消收藏必须与计数维护保持一致。

## 用户收藏、热门与分类查询

`resource_favorites` 是跨设备用户收藏的唯一事实源，主键必须为 `(user_id, resource_id)`。用户在任意设备登录后，先读取该表取得收藏资源，再按需要下载可运行版本和本地缓存；本地缓存的删除不会删除收藏。

- 收藏关联稳定的 `resources.id`，所以组件发布新版本后收藏不丢失，也不会按版本重复计数。
- 本地标题和字幕不写入 `resource_favorites`，始终以本地组件显示。
- 收藏与取消收藏必须在数据库事务中通过触发器或数据库函数原子维护 `resources.favorite_count`，客户端及 Edge Function 不得直接写计数。
- “热门”第一版严格定义为当前具有资源库访问权限的已登录用户的唯一收藏数量；不混入浏览量、点击量、时间衰减或人工权重。将来需要趋势时新增独立筛选。
- 必须提供受控的计数重算任务，用于修复历史异常，但不能作为正常请求路径。
- 资源目录接口还必须返回当前用户的 `is_favorite` 状态；收藏操作返回更新后的 `favorite` 和 `favoriteCount`，界面只更新对应卡片，热门列表则重新请求当前页。

固定筛选与二级业务分类可组合，不相互替代：

| 筛选 | 数据来源 | 排序 |
| --- | --- | --- |
| 我的收藏 | 当前用户的 `resource_favorites` | 收藏时间倒序 |
| 最新 | 已发布 `resources` | `published_at desc` |
| 热门 | 已发布 `resources` | `favorite_count desc, published_at desc, id desc` |
| 二级分类 | 叠加 `category_id` 条件 | 保持当前固定筛选排序 |

因此“热门矩形”“最新三角形”“我收藏的标题”均是合法查询。热门查询必须有覆盖 `tab_key`、`category_id`、`favorite_count desc` 的索引；已归档或撤回资源不出现在普通最新/热门列表，但保留用户收藏历史和旧项目可追溯性。

## 安全边界

远端组件只能加载受控发布器校验、哈希固定且服务器允许的版本。运行时不得访问认证令牌、项目文件 API 或未经清单登记的网络资源；动态加载未登记的 URL 必须拒绝。单个组件运行异常只能使该实例失败，不能中断编辑器。

## 验收

1. 导入页不会请求或显示公共组件。
2. 每个非导入 Tab 初始显示“我的收藏”。
3. 文本 Tab 的本地标题和字幕在“我的收藏”中置顶，并且不会被 Supabase 结果覆盖。
4. 公共资源可在最新、热门、收藏及其真实二级分类之间筛选；最新按发布时间，热门按收藏数。
5. 卡片仅显示名称和收藏数量，或本地标志。
6. 所有卡片的添加和收藏入口共用实现；添加后的公共组件进入本地缓存。
7. 所有可插入组件带有 `target`；缺失时安全阻止插入。
8. 低分辨率 MP4 可在卡片/预览窗口中播放；远端、本地缓存和本地固定组件均有各自的 MP4 预览来源。
9. 组合动画在不同作者帧、项目帧率、预览和导出路径下保持同一关键帧结果。
10. 属性与关键帧仅能修改清单白名单中的项目；未知、越界或不兼容值被拒绝。
11. 本地缓存缺少包、资产、清单或 MP4，或存在哈希不一致时，不可离线预览、插入或导出。
12. 已插入项目的实例锁定组件版本；远端更新不会静默改变其效果。
13. “我的收藏”按用户收藏记录查询；热门和最新分别按收藏数和发布时间排序。
14. 同一用户在多台设备收藏同一资源只计一次；换设备登录后收藏记录完整恢复。
15. 固定筛选可与二级业务分类组合，热门分类按收藏数、发布时间和资源 ID 稳定排序。
16. 同一组件新版本发布不丢收藏，不改变已插入实例；仅显式、可撤销且通过迁移验证的操作可升级实例。
