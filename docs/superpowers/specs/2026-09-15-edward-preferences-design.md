# Edward 0.6.0 偏好系统设计

## 状态

- 状态：设计已确认，等待实现计划
- 范围：Edward 0.6.0 的本地偏好统计、默认值应用和可选云端同步
- 不包含：项目文件迁移、现有片段改写、组件渲染改造

## 1. 目标与边界

偏好系统用于学习用户在创建新素材或新组件时反复确认的属性，并为下一次创建提供默认值。偏好是设备级数据，跨项目共享，但不属于任何项目。

偏好系统不得修改已有片段、已有素材或已有组件，也不得在打开项目时主动向用户建议替换。`project.json` 仍是项目唯一事实源；偏好不能写入项目 JSON、素材库或 FableCut 项目数据目录。

Edward 0.6.0 继续使用 FableCut 的统一浏览器场景作为预览和导出真源。偏好服务只提供原生属性数据，不解析、转换或生成 Component IR，不参与 React、HTML/CSS、SVG、GSAP 的渲染。

## 2. 总体架构

```text
Edward Qt 主进程
 └─ PreferenceStore
     ├─ 内存待提交队列
     ├─ SQLite 事实库
     ├─ 三套派生偏好方案
     └─ 可选 Supabase 同步
          ↑
       窄接口/宿主桥接
          ↑
       FableCut 新建素材/组件流程
```

`PreferenceStore` 是唯一写入方。FableCut 不直接访问 SQLite，只调用窄接口读取新增默认值、提交已确认的属性事实和触发批处理。

数据库使用 Edward 应用数据目录中的 `preferences/preferences.sqlite`。安装实例使用随机生成的 installation ID 作为本地设备作用域，不使用硬件指纹。

## 3. 数据模型

### 3.1 事实记录

事实记录是追加式数据，至少包含：

- `eventId`：客户端生成的唯一 ID，用于幂等合并；
- `installationId`：本机安装实例作用域；
- `componentId`、`componentFamily`、`componentVersion`；
- `manifestHash`：属性契约版本；
- `semanticPath`：组件内部语义节点路径；
- `propertyPath`：具体属性路径；
- `valueType`：颜色、整数、浮点、枚举等；
- `value`：经过 manifest 校验的原始值；
- `creationSessionId`：仅用于组合候选的创建会话标识；
- `source`：用户确认、默认应用等；默认应用不得计入学习；
- `createdAt`。

项目 ID、项目名称、素材路径和时间线信息只允许留在内存上下文中，不落库、不上传。

### 3.2 派生方案

每个有效组件身份最多生成三套方案：

- A：最高频且通过稳定性门槛的方案；
- B：第二高频方案；
- C：第三高频方案。

派生方案可以删除并重新计算，事实记录不依赖方案缓存。数据库损坏时可回退系统默认值并重建缓存，不需要崩溃恢复日志。

## 4. 属性隔离与匹配

任何统计和读取都必须使用完整身份键：

```text
componentId + componentFamily + componentVersion + manifestHash
+ semanticPath + propertyPath + valueType
```

因此文字颜色、边框颜色、SVG `stroke` 和 HTML `color` 不会互相污染。

读取顺序固定为：

1. 组件身份精确匹配；
2. 组件族匹配；
3. 全局属性类别匹配；
4. 系统默认值。

只有 manifest 明确声明允许继承时才可回退到下一层，禁止模糊匹配、名称相似匹配和路径猜测。组件版本或 manifest 变化后，旧事实不能直接套用，除非存在明确的兼容声明。

manifest 仅是属性身份、类型、范围和继承规则的契约，不是渲染转换层。

## 5. 学习规则

### 5.1 只记录确认值

只记录用户确认的最终属性：颜色选择完成、滑块松开、输入框失焦或回车、属性面板确认，以及新建组件设置完成。

不记录拖动中间值、动画中间值、自动填充值、打开项目读取值、导入项目已有值，也不记录修改后恢复原值的过程。

默认应用必须带有内部来源标记，避免“系统自动填入”反向污染统计。

### 5.2 单属性与组合

单属性分别统计频率、最近使用时间、确认次数和有效编辑次数。

组合候选只从同一次新建组件设置会话中产生。不同项目、不同组件或不同时间段的事实不得随意拼接。若没有足够的组合证据，则只使用稳定的单属性默认值，不生成虚假的完整组合。

方案至少满足以下之一才可成为默认 A：

- 至少三次明确确认；
- 至少来自两次不同的新建会话。

排序同时考虑频率、时间衰减、组合完整度、实际共现次数和 manifest 合法性。

## 6. 批处理与收敛

### 6.1 事实批处理触发

内存队列只在以下时机写入 SQLite：

1. 300 秒没有有效偏好操作；
2. 切换或关闭项目；
3. Edward 正常退出；
4. 开始导出。

使用 SQLite WAL 和单事务批量写入。崩溃或强制退出导致的未写入内存事实可以丢失，因为偏好不是项目关键数据。

### 6.2 方案收敛触发

方案只在以下时机后台收敛：

1. 闲置批次写入后；
2. 打开项目后，且存在脏数据；
3. 开始导出时；
4. 设置中的“立即更新偏好”。

关闭项目只保证事实落盘，不强制等待完整收敛。收敛只处理脏作用域，不扫描全部历史数据。

运行状态为：

```text
CLEAN → PENDING_MEMORY → EVENTS_FLUSHING → PROFILE_DIRTY
      → PROFILE_COMPILING → READY
```

同一时间只允许一个写事务和一次收敛。新批次使用递增 revision，不覆盖正在处理的批次。收敛失败时保留上一版有效方案。

## 7. FableCut 接口与应用时机

最小接口为：

```text
getCreationPreferences(componentIdentity)
recordConfirmedPropertyChange(observation)
flushPendingPreferences()
compilePreferences()
uploadPreferences()
downloadPreferences()
```

新增组件流程为：

```text
读取 A/B/C
→ 校验 manifest
→ 合并系统默认值
→ 创建组件实例
→ 将最终 props 交给原生运行时
```

已有组件不会重新读取方案，也不会因后台收敛而改变。

在属性检查器中，“名称”位置改为“偏好”入口，用于选择新增时使用的 A/B/C 方案；“名称”移动到“基础信息”区域并保留编辑能力。选中已有片段时，偏好入口只读或不适用，不能借此改写片段。

## 8. Supabase 同步

云端同步必须由用户在设置中主动执行上传或下载。同步内容只包括经过校验的偏好事实和版本信息，不包括项目、素材、路径或时间线。

同步采用事实合并而不是方案覆盖：

```text
本地事实 + 云端事实 → eventId 去重 → 本地重新收敛
```

下载事实必须重新校验组件身份、manifestHash、属性路径、类型和值范围。云端失败不影响本地偏好和编辑流程。

## 9. 错误、性能和降级

- 编辑期间不写磁盘、不重新计算方案；
- SQLite 使用 WAL 和后台线程；
- 待提交队列和单次批次有数量上限；
- 偏好服务故障时回退系统默认值；
- 导出开始时只等待事实批次事务完成，不等待方案收敛；
- 方案收敛使用上一版有效方案，不能阻塞预览或导出；
- 数据库损坏时隔离损坏文件、重建空库并继续工作；
- 不增加崩溃恢复日志，不把偏好升级为项目关键数据。

## 10. 验收标准

1. 新建组件能读取方案 A，并可选择 B/C；已有片段完全不变。
2. 文字颜色、边框颜色和不同组件内部同名属性统计完全隔离。
3. 默认应用、动画中间值、拖动中间值和导入项目值不会进入学习事实。
4. 300 秒闲置、切换/关闭项目、正常退出和导出都会按规则批量处理。
5. 偏好数据不出现在 `project.json`、项目导出包或素材库中。
6. SQLite 写入和收敛不阻塞正常编辑，偏好故障不影响预览与导出。
7. Supabase 上传/下载必须显式触发，且采用事实合并和 manifest 校验。
8. 不引入 Component IR、理解层或任何组件转换层；组件仍由原生运行时直接预览和导出。

## 11. 明确不做的事情

- 不自动改写已有组件属性；
- 不把偏好写入项目文件；
- 不用通用属性名称做跨组件统计；
- 不根据模糊名称猜测组件身份；
- 不实时记录每个输入事件；
- 不因偏好失败阻塞编辑器、预览或导出；
- 不把 Supabase 作为本地运行的必需依赖。
