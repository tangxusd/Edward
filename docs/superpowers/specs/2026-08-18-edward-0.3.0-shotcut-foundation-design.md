# Edward 0.3.0 Shotcut/MLT 基座设计规格

## 目标

在保留 Edward 已确认视觉稿和类似剪映的工作流前提下，以 MLT 作为媒体引擎，选择性吸收 Shotcut 已验证的时间线编辑逻辑，逐级实现基础剪辑、动画组件、外部渲染插件和资源库上传能力。

## 已确认范围

0.3.0 优先实现视频剪辑与动画叠加，不追求 Shotcut 的完整功能。用户明确不把强大的音频、波形、调色系统和完整滤镜库作为首要目标；关键能力是片段编辑、关键帧、贝塞尔曲线、透明组件叠加、预览窗拖拽和剪映式交互。

## 架构原则

### Edward 是编辑真相源

工程文件由 Edward 自己的工程模型保存，包含视频片段、轨道、播放头、标准组件树、插件组件实例、关键帧、资源引用和插件依赖。React、Remotion、HyperFrames 和 MLT 都不能成为工程编辑数据的唯一真相源。

### MLT 是媒体运行时

MLT 负责媒体解码、时间映射、基础片段合成和导出所需的媒体处理。Shotcut 的完整应用界面不进入 Edward。

### Shotcut 选择性来源

在许可证和依赖审核通过后，只参考或移植与以下能力直接相关的 Shotcut/时间线逻辑：片段模型、轨道状态、播放头、分割、裁切、删除、波纹删除、拖动吸附、选择、链接/解除链接和撤销/重做边界。Shotcut 的 QML 界面、波形、调色、音频混音器、完整滤镜库和资源库不进入 0.3.0 基座。

### Component IR 是组件标准

所有可编辑动画组件使用版本化的 Edward Component IR。IR 表达递归组件树、节点类型、属性、资源、关键帧和贝塞尔曲线。React 是 IR 的一个渲染后端，Remotion/HyperFrames 是外部插件渲染后端，不能替代 IR。

## 运行时分层

```text
Edward UI and commands

```

## 基础剪辑能力

第一阶段只要求视频主流程闭环：导入视频、读取媒体元数据、放入视频轨道、播放、播放头定位、片段拖动、左右裁切、播放头处分割、普通删除、波纹删除、轨道新增/删除、片段选择、撤销/重做、基础吸附、保存和重新打开工程。

音频轨道可以保留最低限度的媒体兼容能力，但不实现音频波形、混音器和复杂音频编辑作为 0.3.0 的前置能力。

## 动画组件能力

标准组件第一批包含 `Container`、`Text`、`Shape`、`Image` 和 `SVG`。节点支持父子嵌套；父节点的位置、缩放、旋转和透明度影响子节点，子节点仍可以用局部坐标单独编辑。

关键帧系统至少支持位置、缩放、旋转、透明度、文字属性和形状属性；时间插值和空间路径支持线性、保持和贝塞尔曲线。预览窗拖拽通过命令层修改 IR，并在当前播放头写入或更新关键帧。

## 外部插件边界

用户可以独立安装 Remotion、HyperFrames 或其他受控插件。Edward 不把插件代码加载进主进程，而使用独立插件进程和版本化 RPC 协议。插件 manifest 必须声明入口、版本、能力、依赖和权限。

插件至少提供以下能力：

- 描述组件和可编辑属性；
- 根据 frame、fps、尺寸和 props 渲染透明预览帧；
- 根据同一份参数执行导出渲染；
- 报告缺依赖、超时、崩溃和不支持的属性。

插件只返回透明帧而不提供组件描述时，Edward 只能编辑整个透明层的位置、缩放、旋转、透明度和时间线区间，不能编辑插件内部节点。

插件沙盒默认禁止网络，限制可读项目素材、可写缓存目录、运行时间、内存和 CPU；插件崩溃或超时不得导致主程序退出。

## AI、属性和拖拽编辑

AI 对话、属性面板和预览窗拖拽都必须生成统一编辑命令，并修改同一份 Component IR 或插件实例参数。AI 不直接执行任意 JavaScript 或 CSS。

```text
AI command / property edit / preview drag
                    |
              command validator
                    |
        project model or Component IR
                    |
       native renderer or plugin props
```

对于外部插件，只有 manifest 声明的 `editableProps` 可以进入 Edward 属性面板和 AI 编辑命令；未声明的插件内部结构保持插件私有。

## 资源库和 Supabase 上传

资源库保存版本化 Edward Component Package，而不是单独的 React 源码、插件工程或烘焙 PNG。组件包至少包含 manifest、Component IR、props schema、关键帧、资源、缩略图和插件依赖声明。

标准组件和插件组件可以共存于同一资源库，但 manifest 必须明确兼容等级：标准组件无需外部插件；插件组件声明插件 ID、版本范围和可编辑属性；缺失插件时显示依赖状态而不损坏工程。

用户通过 AI 或属性面板生成并确认组件后，选择分类并保存本地组件包。登录用户通过认证后的 Edge Function 将组件包和资源上传到 Supabase 私有 Storage 与待审核表，记录用户 ID、用户名、组件版本、插件依赖和状态。管理员后续审核通过后复制到正式公开资源库。

上传前禁止组件包引用用户本机绝对路径；资源必须以组件包内资源 ID 引用。匿名用户可以本地使用和保存，但不能静默上传云端。

## 视觉和交互约束

- Edward 继续使用已确认视觉稿，不采用 Shotcut 的 QML 视觉界面。
- 系统原生标题栏保留红黄绿或 Windows 原生窗口控制，不在页面内模拟标题栏。
- 工作台、资源库、设置和弹窗继续沿用已确认的深色视觉基线。
- 时间线行为可以参考 Shotcut，但视觉、轨道布局、按钮、颜色和交互反馈必须按 Edward 视觉稿实现。

## 分阶段验收门

### 0.3.0-1 媒体基座

导入、元数据、单视频轨道、播放头、播放、保存/重开通过后，才能进入时间线编辑。

### 0.3.0-2 时间线编辑

分割、裁切、删除、波纹删除、拖动、吸附、轨道、选择、链接/解除链接、撤销/重做均有失败测试和通过测试后，才能进入预览合成。

### 0.3.0-3 Edward 时间线视觉层

时间线按 Edward 视觉稿运行；素材库拖入、播放头冲突处理和片段状态可观察且可验证。

### 0.3.0-4 预览与导出

预览和离屏导出使用同一个 RenderGraph；基础视频可以导出并与预览帧一致。

### 0.3.0-5 标准动画组件

父子组件、属性、关键帧、贝塞尔、预览拖拽、透明叠加和导出全部闭环。

### 0.3.0-6 外部插件

插件独立安装、RPC、透明预览帧、透明导出层、公开属性编辑和故障隔离通过后，才能进入插件资源库。

### 0.3.0-7 资源库上传

Component Package 校验、本地分类保存、认证上传、待审核记录和缺少插件状态通过后，才进入公开资源审核流程。

## 明确不纳入 0.3.0 前置范围

- 完整 Shotcut UI；
- 高级音频和波形；
- 调色页面；
- 完整滤镜和转场生态；
- 任意 HTML/React 自动获得全部内部节点编辑能力；
- 未声明属性的插件内部 DOM 编辑；
- 将所有 AI 模型捆绑进 Edward 安装包。

## 风险和处理

- Shotcut/MLT 许可证与移植范围：在导入代码前完成源文件归属、许可证和通知清单审核。
- 预览与导出不一致：RenderGraph 使用统一工程帧和统一组件求值，禁止 QML 绘制第二套画面。
- 插件缺失或版本不兼容：manifest 明确依赖，工程保留实例但显示依赖状态。
- 资源库格式演进：Component IR 使用版本字段和迁移器，上传与下载都执行 schema 校验。
- 现有 0.2.0 工作树未提交改动：创建 0.3.0 分支前只从已冻结基线建立，不覆盖或回滚现有未提交文件。
