# Edward 认证生命周期设计

## 目标

将注册、邮箱确认、登录、找回密码和本地会话统一为一个由服务端裁决的认证状态机。用户界面只显示中文业务反馈；Supabase Auth 负责身份凭据和邮件令牌，Edward 负责业务状态、设备限制和期限管理。

## 范围与约束

- 注册以邮箱确认成功为完成条件；未确认用户不是已登录用户。
- 注册确认邮件、找回密码邮件均在发出后 10 分钟失效。
- 同一设备与同一邮箱在待确认期间只能有一条注册；重复操作不创建第二个用户。
- 硬件序列号和物理 MAC 地址由原生端后台采集，仅服务端管理员受控访问；不得出现在用户界面、普通日志、客户端持久化或公开 API 响应中。
- 同一设备、同一邮箱的限制只针对有效待确认或已确认账户；待确认注册超过 10 分钟被释放后允许重新注册。
- 发起找回密码后，账户进入恢复锁定状态；在新密码通过邮件链接成功设置前，正确旧密码也不得登录。
- 登录会话持久化沿用当前原生安全存储，但每次启动和使用受保护资源前必须由服务端刷新/确认。
- 所有用户可见文案为中文；内部错误码不得透传至界面。

## 认证状态

### 账户状态

| 状态 | 含义 | 允许行为 |
| --- | --- | --- |
| `registration_pending` | Auth 用户已创建但邮箱未确认 | 重发确认邮件；同设备同邮箱重复注册返回待确认提示 |
| `active` | 邮箱已确认且没有恢复锁 | 登录、订阅、资源访问 |
| `recovery_locked` | 已发出密码重置邮件，尚未完成密码更新 | 仅允许完成当前或重新发起找回；禁止登录 |
| `registration_expired` | 未确认注册已超过 10 分钟 | 清理 Auth 用户、资料和待确认绑定；邮箱可重新注册 |

恢复锁是活跃账户的独立状态，不改变邮箱确认状态或订阅权益。

## 设备身份

原生端在注册和找回密码请求前读取硬件序列号与当前主物理网卡 MAC 地址。平台实现必须从系统原生接口读取，不允许用浏览器指纹、随机 ID、IP 地址或可变网络信息替代。

客户端将两个原始值仅通过 TLS 发送至认证 Function。Function 完成以下工作：

1. 使用仅存在于 Function Secret 中的版本化 HMAC 密钥，计算 `device_fingerprint`，作为等值查询和限流键。
2. 使用独立的服务端加密密钥，加密序列号和 MAC 后保存到管理员审计记录。
3. 不在数据库公开视图、JWT、API 返回体、客户端设置、诊断日志或错误消息中返回原始值、密文或指纹。
4. 对读取失败、空值或格式不合法的设备信息拒绝注册/找回请求，并仅返回中文说明“无法读取设备标识，请检查系统权限后重试”。

管理员受控审计记录仅用于识别恶意重复注册和安全调查；业务判定使用 HMAC 指纹，避免在常规查询中接触原始硬件信息。

## 注册流程

1. 原生端采集设备信息，FableCut 注册页提交邮箱、密码、用户名和设备信息给 `auth-register`。
2. Function 在数据库事务中锁定 `(email_normalized, device_fingerprint)`：
   - 存在 `registration_pending` 且未到期：不创建用户，按邮件发送频率决定是否重发，返回“确认邮件已发送，请在 10 分钟内确认完成”。
   - 存在已确认账户：返回“该邮箱已完成注册，请直接登录”。
   - 存在已过期待确认记录：先完成清理并确认 Auth 用户删除成功，再允许新注册。
3. Function 创建 Supabase Auth 用户和 Edward 资料，写入 10 分钟到期的待确认记录，并发送带 `flow=signup` 的确认邮件。
4. Function 返回 `emailVerificationRequired: true`；客户端显示“确认邮件已发送，请在 10 分钟内确认完成”，不保存登录 session，不打开订阅面板。
5. 邮件链接验证成功后，确认落地页先建立 Supabase 的验证码会话，再调用受保护的 `auth-registration-confirm` 完成接口，原子地将待确认记录切换为 `active`。页面提示“邮箱已确认，请返回 Edward 登录”。
6. 每分钟清理任务扫描到期的待确认记录；删除相应的 Auth 用户、资料及有效绑定。注册 Function 同时执行按需清理，因此定时任务稍有延迟也不会阻止下一次注册。

生产 Supabase Auth 的 Confirm email 必须开启，Email OTP expiry 必须设为 600 秒；Edward 记录的 `expires_at` 使用服务端时间并同样为 10 分钟，不以客户端时钟判断。

## 登录与会话流程

1. 登录请求先由 `auth-login` 标准化邮箱/用户名，并查询 Edward 账户状态。
2. `registration_pending` 返回“确认邮件已发送，请在 10 分钟内确认完成”；`recovery_locked` 返回“密码重置进行中，请通过邮件链接完成重设后再登录”。两者都不调用密码登录接口。
3. 只有 `active` 才调用 Supabase `signInWithPassword`。所有底层错误归一为“邮箱或密码不正确”或受控中文限流说明，避免用户界面泄露内部错误码。
4. 成功响应由原生端保存到当前安全会话存储；启动恢复、刷新令牌、标题栏登录状态、资源接口与订阅面板均只使用经 `auth-session` 服务端确认的会话。
5. 明确点击“退出登录”才清除本地会话和标题栏已登录状态；关闭订阅面板不清除会话。

## 找回密码流程

1. 用户输入邮箱并请求找回；原生端附带设备身份。
2. Function 对有效已确认账户创建或替换恢复锁，锁的邮件令牌到期时间为 10 分钟；随后发送 `flow=recovery` 链接。页面一律显示“如该邮箱可使用，重置链接已发送，请检查邮箱”，不暴露账户是否存在。
3. 恢复锁存在期间，登录 Function 一律拒绝密码登录，即使旧密码正确。
4. 落地页验证恢复链接后允许用户两次输入一致的新密码。密码更新成功后调用认证完成接口：验证当前恢复 session，关闭对应恢复锁并记录完成时间。
5. 10 分钟失效的链接不能更新密码；用户可重新发起找回，新的邮件替换旧邮件。恢复锁保持登录阻断，直到有效的找回流程完成，避免超时后旧密码重新获得访问权。

## 用户可见反馈合同

| 场景 | 中文反馈 |
| --- | --- |
| 注册邮件已发送或待确认重试 | 确认邮件已发送，请在 10 分钟内确认完成。 |
| 已注册 | 该邮箱已完成注册，请直接登录。 |
| 确认链接过期 | 确认链接已失效或已过期，请重新发送确认邮件。 |
| 找回邮件已发送 | 如该邮箱可使用，重置链接已发送，请检查邮箱。 |
| 找回锁定登录 | 密码重置进行中，请通过邮件链接完成重设后再登录。 |
| 找回链接过期 | 重置链接已失效或已过期，请重新发起找回密码。 |
| 无法采集设备信息 | 无法读取设备标识，请检查系统权限后重试。 |
| 邮件服务不可用 | 邮件暂时无法发送，请稍后重试。 |
| 登录凭据无效 | 邮箱或密码不正确。 |

## 服务端边界

- 新增认证状态表、设备安全审计表和恢复锁表；全部启用 RLS，普通 `authenticated` 与 `anon` 角色无读取原始设备数据的权限。
- 所有跨表状态转换通过单一的认证 Function/RPC 完成；客户端、FableCut 本地服务和邮件落地页不得直接修改状态表。
- 未确认用户清理、设备风控和恢复锁判断以数据库服务端时间为准。
- Function 日志只记录请求 ID、状态迁移、HMAC 指纹前缀和安全事件类别；不记录邮箱全文、密码、令牌、硬件序列号或 MAC。

## 验收与测试

1. 首次注册仅生成待确认账户和 10 分钟确认邮件，客户端不取得 session。
2. 10 分钟内同设备同邮箱重复注册不创建第二个用户，返回中文待确认反馈。
3. 到期用户被删除；相同邮箱和设备可以再次注册。
4. 已确认账户重复注册只返回中文登录提示。
5. 过期确认链接显示中文重发入口；新链接确认后账户变为 active。
6. 任一用户可见认证错误均不含底层英文错误码。
7. 找回密码后登录被阻断；密码更新成功后恢复登录；链接过期后仍需完成新的找回流程才可登录。
8. 设备信息未出现在普通 API、日志与客户端持久化；管理员审计路径可追踪加密记录。
9. 应用重启后有效会话恢复，失效或恢复锁状态立即反映到标题栏和订阅入口。
